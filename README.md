# folder-encrypt

把一个文件夹拖到程序图标上，它就用文件夹名开头的 8 位日期当密码，压成一个连文件名一起加密的 7z 包。压缩和加密都在程序内部完成，不调用 WinRAR，也不需要装 Python。

系统要求 Windows 10/11 64 位。下载地址见本仓库的 Releases 页面。

## 使用场景

工作里经常要整包发资料，又不希望内容在路上被人随手翻到。评审资料、投标文件、报名表、工资表、试验原始数据，发的时候都是同一个动作：压成一个包，加个密码，再告诉对方密码是多少。

密码本身往往不用现编。这类文件夹的命名习惯就是日期打头，比如 20260812会议评审资料，看到名字就知道是哪天的活。既然如此，密码直接取这个名字的前 8 位，收发两头都不用额外记东西。

也有只加密内容不够的场合。压缩包不加密文件名时，不输密码就能列出里面有哪些文件，光看清单已经能猜出内容，比如一份写着具体人名的工资表。这种时候需要连文件清单一并加密。

## 问题解决方案

早先的做法是写个脚本调用 WinRAR 的 `-hp` 参数，把文件夹名开头的 8 位数字取出来当密码。能跑，但有几处不踏实。

命令行里的路径写死成 `C:\Program Files\WinRAR\Rar.exe`，WinRAR 装在别的盘、或者装的是 32 位版本，程序就直接报错，而且没做存在性判断，抛出来的是一串异常。压缩前会先把同名旧包删掉，万一同一次压缩中途失败，旧文件已经没了。密码是当命令行参数递给 Rar.exe 的，任务管理器里能看到完整命令行。另外只要有一个文件被别的程序占用、读不出来，整包就失败，前面压好的部分也一并丢掉。

这个版本把这四点都改掉了。压缩加密改由程序自己完成，用 7z 容器加 AES-256，同时打开头部加密，文件清单和文件内容一样是密文，不输密码连里面有哪些文件名都看不到。压缩时先写一个 `.part` 临时文件，全部写完成功才顶替正式文件，失败就删掉临时文件，原来的包不动。密码在程序内部传给加密模块，不出现在命令行里。单个文件读不了就跳过，最后把跳过的文件列出来，其余照常打包。

压缩算法用 LZMA2，级别定在 1 级，偏向速度。38.3MB、798 个文件的目录实测约 5 秒压成 11.96MB。级别在源码顶部的 `COMPRESS_PRESET` 里，想要更高压缩率改这一处重新打包即可，输出的 7z 格式和接收方兼容性不受影响。

## 使用注意事项

1. 文件夹名必须以 8 位日期开头，程序取这 8 位当密码。名字不符合要求，或者拖进来的不是文件夹，程序会提示并停下。

2. 压缩包输出到该文件夹的上一级目录，文件名与文件夹同名，扩展名 `.7z`。同名文件已存在会直接覆盖。

3. 密码就是压缩包文件名的前 8 位，拿到压缩包的人同时也拿到了密码。它防的是发错人、传错群、文件被随手打开，不防有意翻找的人。确需保密，把压缩包改成与文件夹无关的名字再发。

4. 接收方用 7-Zip、WinRAR、Bandizip、PeaZip 这类工具都能解开，输入密码后可以看到文件清单，本机用 WinRAR 实测通过。Windows 资源管理器自带的解压不认加密的 7z，会直接报错，发之前最好先说明。

5. 原文件夹不会被删除也不会被改动，压缩完成只是在旁边多出一个 .7z 文件。需要清除明文的话自行处理。

6. 程序每次启动会先把自身解包到临时目录，固定花掉约 1.1 秒，之后才开始压缩。文件夹很小时，这 1 秒多会比较明显。

7. exe 未做数字签名，首次运行可能被安全软件拦截或提示，加白名单即可。

8. 仓库里的 `folder-encrypt.spec` 是打包配置，但里面的 `.pyd` 路径指向本机 Python 目录，换机器要改。完整的打包命令、需要的 `--add-binary` 与 `--exclude-module` 参数，都记在同目录的 `使用说明.txt` 里。
